# 📁 projects（專案）

**alpha（尚未實機驗證）**。追蹤好幾個專案「停在哪、為什麼停、回來先做什麼」。每個專案只有三個短答案，不是一頁 wiki。

| 指令 | 做什麼 |
|---|---|
| `/proj <名稱> [path=資料夾]` | 追蹤一個新專案 |
| `/proj_list [狀態\|cold\|due]` | 看專案；不寫＝全部（放下的不列）；`cold` 冷掉的、`due` 說好要回來看的 |
| `/proj_show <編號>` | 一個專案的細節 |
| `/proj_update <編號> [name= state= status= next= path= tags= …]` | 改欄位；值寫 `-` ＝清掉 |
| `/proj_pause <編號> [reason= reason_note= reason_ref= resume_at= next=]` | 先停一下：記為什麼停、讓位給誰、什麼時候回來看 |
| `/proj_resume <編號>` | 回來做（回訪日清掉，原因留著） |
| `/proj_scan [編號]` | 掃資料夾算「真的多久沒動」 |
| `/proj_rm <編號>` | 停止追蹤（⚠️ 危險：AI 要做會先送確認卡；先放進回收區，`/proj_restore` 可復原最近 10 筆） |
| `/proj_reason_add`、`/proj_reason_retire` | 加／退休自訂的暫停原因 |

**狀態**：💡 構想 → 🔥 進行中 → ✅ 完成；⏸ 暫停中、📦 放下了（只是標記，資料不刪）；🗄 保管中（備份、別人的專案：不追進度，不算冷掉）。
**暫停原因**：⛽ 額度用完、☄️ 隕石插隊、🧱 卡住了、🧭 換路了，也可以自己加；前兩個可以指定「讓位給哪個專案」，變成一筆有對象的紀錄。

## 網頁畫面

在 SYNOX 的工具頁按「打開」：清單、依狀態與原因篩選、🧊 冷掉的（程式量的）、🔖 說好回來看的（你約的）、一鍵 ⏸／▶、編輯、停止追蹤後 12 秒內可以復原。

## 資料與安全

- 專案紀錄存在 SYNOX 保管箱（加密，每人一份）。檔名與格式見 `engine/model.py`。
- **會讀你填的資料夾（只讀）**：掃描只看第一層檔案的修改時間，以及 `.git/logs/HEAD` 最後一行的時間（不呼叫 git、不開別的程式、不寫任何東西）。
  所以宣告 `filesystem:any`、`access: owner`（只有擁有者能用）。路徑只來自你自己填的專案位置，沒有預設路徑；相對路徑不收。不填位置就完全不碰檔案。
- 不連網、不開別的程式。
- 從舊的個人管家搬來時**沒有帶**的東西：用檔案總管／VS Code／終端機開專案（要開別的程式）、`${VAR}` 路徑變數、資料夾挑選視窗、批次修搬家的路徑、方向（人生目標）欄位與週檢。

## 跟別的工具的關係

完全獨立，裝了就能用。SYNOX 目前沒有「選用的跨工具連結」機制（`requires.packs` 是硬相依），所以這個工具不 import、不呼叫別的工具；
它留了一個出口 `due_back`（網頁畫面的讀；`provides: projects.due_back`）：回說好要回來看的專案與日期，給之後的行事曆之類的工具選用。
