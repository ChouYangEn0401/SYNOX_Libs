# 🔑 USB 鑰匙（usb-keys）0.1.0-alpha.1

把**很多支隨身碟**登記成「鑰匙」，再選一把來**鎖訊息或檔案**。要解開時，那支隨身碟一定要插著。
加密、驗證隨身碟全部由 [usbtether](https://github.com/ChouYangEn0401/usbtether) 函式庫做；這個工具只負責指令、畫面、權限和白話訊息，
自己不寫任何加密。

> 這是 **SYNOX 工具庫（SYNOX_Libs）** 的工具（🧪 alpha，**尚未實機驗證**：只用「假的隨身碟」測過，還沒在真的隨身碟上試過，
> 先不要拿來鎖唯一一份的重要資料）。只給擁有者用（`access: owner`）。

## 先懂這三件事

1. **鑰匙在隨身碟上**：登記時，usbtether 會在隨身碟寫一個小資料夾 `.usbtether`（裡面是這把鑰匙的私鑰）。
   SYNOX 這邊只存「公鑰＋這支碟的硬體指紋＋你取的名字」。複製 `.usbtether` 到別支碟上**沒有用**（硬體指紋對不上）。
2. **保護方式**（登記時選）：
   | 選項 | 意思 |
   |---|---|
   | 💻 記住在這台（建議） | 在這台電腦用不用打密碼；解鎖資料用 Windows 的 DPAPI 封在這台電腦、這個 Windows 帳號。換電腦就打不開 |
   | 🔒 要密碼 | 每次用都要在畫面輸入密碼。**密碼忘了，用它鎖的東西就打不開** |
   | ⚠️ 不保護 | 撿到這支碟的人也能解開。不建議 |
3. **救不回來的動作**：**撤銷**一把鑰匙、或**重新登記**一支已經登記過的碟，用舊鑰匙鎖過的訊息和檔案**永遠打不開**。
   這兩個動作**一定要先用手機驗證器解鎖**（SYNOX 的 `/unlock`；`pack.json` 的 `stepup`），還沒設定驗證器就不能做。
   畫面與指令都會先警告，還要你再打一次鑰匙名字（或「覆蓋」）才做。隨身碟弄丟或壞掉，也一樣打不開——重要的東西請另外留備份。

## 指令

| 指令 | 做什麼 | AI 能不能叫 |
|---|---|---|
| `/usb_keys` | 列出鑰匙：名字、哪支碟、保護方式、現在有沒有插著 | ✅ |
| `/usb_drives` | 列出插著的隨身碟，哪些可以登記 | ✅ |
| `/usb_lock <鑰匙> <訊息>`、`/usb_lock <鑰匙> file=1/報告.pdf` | 用那把鑰匙鎖一段訊息（回你 `utmsg1:` 開頭的一段字），或鎖一個檔（旁邊多一個 `.utenc`，原檔不刪） | ✅ |
| `/usb_unlock_check <utmsg1:…>`、`/usb_unlock_check file=1/報告.pdf.utenc` | 看要哪把鑰匙才打得開、那支碟有沒有插著（**不解開**） | ✅ |
| `/usb_unlock file=1/報告.pdf.utenc` | 解開檔案（旁邊多一個原檔名的檔，`.utenc` 不刪；回覆只有「資料夾編號/檔名」）。**訊息只能在畫面上解開**，聊天裡打 `/usb_unlock utmsg1:…` 會被拒 | ❌ 只有你本人 |
| `/usb_register <磁碟代號> <名字> [protect=記住\|密碼\|不保護]` | 登記一支隨身碟 | ❌ 只有你本人 |
| `/usb_reregister …  confirm=覆蓋` | 重新登記（**舊鑰匙永遠失效**；要先用手機驗證器解鎖） | ❌ 只有你本人 |
| `/usb_revoke <鑰匙> confirm=<再打一次名字>` | 撤銷（**用它鎖的東西永遠打不開**；要先用手機驗證器解鎖） | ❌ 只有你本人 |
| `/usb_lock_pw …` | 用「要密碼」的鑰匙上鎖（密碼只能在畫面輸入） | ❌ 只有你本人 |
| `/usb_folders`、`/usb_folder_add <完整路徑>`、`/usb_folder_rm <編號>` | 設定「可以鎖、解開檔案的資料夾」 | ❌ 只有你本人 |

- 「只有你本人」：`pack.json` 的 `callers` 寫了 `human`（SYNOX 在執行時擋：AI、排程、手機入口都叫不到，AI 的工具清單裡也看不到），
  程式裡也設了 `ai=False`、再用 `kit.require_human()` 檢查一次。
- **密碼不收聊天裡打的**：只要在 Telegram／Discord／終端機打了 `password=…`，工具一律拒絕（也不會拿那個值去試），請你刪掉那則訊息、改到畫面輸入。
  這幾個指令後面的字也不會寫進 log。
- **解開的訊息只在畫面上**：訊息只能在工具畫面解開，解開的字只顯示在畫面上（有「清掉」鈕），不送進聊天、不會變成 AI 的工具結果
  （`/usb_unlock` AI 本來就叫不到）。聊天裡只能解開檔案，回覆只寫解開後的「資料夾編號/檔名」。
- 檔案只能是你設定的資料夾裡面的（`資料夾編號/相對路徑`，或完整路徑；跳出資料夾、符號連結繞出去都擋）。
  鎖好或解開的檔已經存在時不會覆蓋，會請你先移走。

## 畫面

在 SYNOX 網頁的工具頁打開「🔑 USB 鑰匙」的畫面（工具服務，SYNOX 開、只有這台電腦看得到）：

- **鑰匙**：清單、🟢 插著／⚪ 沒插、撤銷（先警告，要再打一次名字，而且要先用手機驗證器解鎖）。
- **登記新的鑰匙**：列出插著的隨身碟 → 選一支 → 取名字、選保護方式（選「要密碼」才出現密碼欄，要打兩次）→ 登記。
  已經有鑰匙資料的碟只能「重新登記」，會先跳確認框、還要打「覆蓋」。
- **鎖／解開一段訊息**：選鑰匙、貼字、（要密碼的鑰匙才填密碼）→ 鎖上／看要哪把鑰匙／解開。解開的字只在這個畫面上，有「清掉」鈕。
- **鎖／解開檔案**：加資料夾 → 在資料夾裡點選檔案 → 鎖上／看要哪把鑰匙／解開。

讀隨身碟一次大約 2 秒；在聊天裡打的指令會丟到背景做，不會卡住 SYNOX。

## 安裝 usbtether（第一次要做，只做一次）

這個工具用 usbtether 0.3.0 函式庫。**SYNOX 現在不會替 kind=python 的工具裝套件**（`requires.pip` 只拿來給第 2 關認得 `import usbtether`、
給你看），而且 usbtether 不在 PyPI，所以要自己裝進 SYNOX 的環境一次：

1. 從 usbtether 的 GitHub 發佈頁（`v0.3.0`）下載 `usbtether-0.3.0-py3-none-any.whl`。
2. 對雜湊（要一模一樣）：`945ee70ff2f3ab14ebc86ad5ab22b68c511542acc91e30db8ac7020114947099`
   （Windows：`certutil -hashfile usbtether-0.3.0-py3-none-any.whl SHA256`）。
3. 在 SYNOX 資料夾：`.venv\Scripts\python.exe -m pip install --no-deps <下載的 .whl>`
   （它只要 `cryptography`，SYNOX 本來就有。）
4. 重新載入工具（或重開 SYNOX）。沒裝好的話，每個指令都會回「usbtether 函式庫還沒裝」，不會壞掉。

## 能力宣告（安裝報告上會看到）

`capabilities: ["filesystem:any", "subprocess"]`。這個工具自己的程式不開檔、不開程式，但它叫的 usbtether 會：

- **filesystem:any**：讀寫你選的檔（只限你設定的資料夾）、在隨身碟上寫 `.usbtether`；
- **subprocess**：在 Windows 用 PowerShell（CIM）讀隨身碟的硬體資訊（不用系統管理員權限）。

不連網、不開網路埠。

## 資料存哪

| 東西 | 在哪 |
|---|---|
| 鑰匙清單（公鑰、硬體指紋、名字） | SYNOX 的 `data/usb-keys/files/keyring/registry.json`；伺服器版是 `data/users/<id>/usb-keys/files/keyring/`。跟 usbtether 命令列預設的那一份分開，兩邊的鑰匙不共用 |
| 「記住在這台」的解鎖資料 | 同一個資料夾的 `secrets/`，Windows DPAPI 封住 |
| 可以用的資料夾、每把鑰匙的保護方式、哪個 `.utenc` 是哪把鑰匙鎖的 | `pack.store`（SYNOX 保管箱，密文） |
| 鑰匙的私鑰 | 隨身碟上的 `.usbtether` |

`.utenc` 檔本身不記是哪把鑰匙鎖的：在這個工具鎖的會記下來；別處鎖的，插著的鑰匙只有一把時會直接用那一把。

## 還沒做的、已知的限制

- 只在 Windows 上設計與測試（usbtether 的 Linux 支援還在實驗）。
- 一次只鎖一個檔，不鎖整個資料夾。
- 同時插好幾支已登記的碟時，解 `.utenc` 要指定 `key=`。
- SYNOX 網頁工具頁（不是這個畫面）上的指令卡，密碼欄是一般文字框；請用這個工具自己的畫面輸入密碼。
