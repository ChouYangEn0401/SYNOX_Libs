# 📅 calendar（行事曆）

**0.2.0-alpha.1（alpha，尚未實機驗證）**：行程有開始與結束、可以跨日、每週重複、撞時間會提醒；有月曆總覽、今日清單與「今天最重要的一件事」；
附一整個網頁畫面（SYNOX 工具頁按「打開」）。原本的指令（`/cal`、`/cal_today`、`/cal_week`、`/cal_list`、`/cal_rm`、`/cal_ics`）照舊能用。

| 指令 | 做什麼 |
|---|---|
| `/cal <時間 標題>` | 加一個行程：`/cal 明天 14:00 看牙醫`、`/cal 下週一下午三點半 開會 location=三樓`、`/cal 11/20 整天 員工旅遊`。<br>跨日：`end_date=2026-11-24`；重複：`repeat=二四 until=2026-12-31`（二四、週末、一到五、`mon,wed` 都行） |
| `/cal_today` | 今天的行程＋今日清單＋撞時間 |
| `/cal_week` | 今天起 7 天的行程 |
| `/cal_list [n]` | 接下來的 n 個行程（預設 10；重複的每一次各算一個） |
| `/cal_month [YYYY-MM]` | 這個月（或指定月份）每天有什麼 |
| `/cal_edit <編號> …` | 改一個行程：`title=`、`date=`、`time=14:00-15:30`、`end_date=`、`location=`、`note=`、`repeat=`、`until=`；沒給的不動，`-` ＝清掉 |
| `/cal_status <編號> <狀態> [原因]` | `planned`（排著）、`done`（完成了）、`not_done`（這次沒做，可寫原因）、`cancelled`（取消了） |
| `/cal_rm <編號>` | 刪掉一個（編號是清單上的 `[3]`，固定不變）。重複行程：`3@2026-11-12` ＝只跳過那一次，`3` ＝整串 |
| `/cal_clash`、`/cal_keep <編號> <編號>` | 看哪些行程撞時間；「兩個都留」之後那一組就不再算沒處理 |
| `/cal_task <事> [date=…] [priority=0-3] [detail=…]` | 今日清單加一張卡片 |
| `/cal_tasks [date=…]`、`/cal_done <卡片>`、`/cal_task_edit`、`/cal_task_rm` | 看、勾起來、改、刪 |
| `/cal_focus <卡片>` | 挑那天**最重要的一件事**（`-` ＝清掉）；清單把它排最前面 |
| `/cal_ics` | 整本行事曆匯出成 `.ics` 檔（含重複規則），在 Google 日曆（設定 → 匯入與匯出）或 iPhone（點開檔案）匯入 |

## 規則

- 看得懂的日期：今天、明天、後天、大後天、今晚、明早、週五／星期五／禮拜五、這週五、下週一、下下週三、3天後、2週後、
  11/12、11月12日、2026-11-12、15號。時間：14:00、14:00-15:30、下午2點、下午兩點半、晚上8點15分、9am、中午。
- 沒寫年的日期今年已經過了就算明年；「15號」過了算下個月；沒寫結束時間預設一小時；沒寫時間＝整天；`22:00-02:00` ＝跨過午夜。
- **撞時間只報告、不擋**：整天的、取消的不算撞。只有你自己的時段：沒有邀請、不寄信、不改別人的時間。
- **重複只做最小版**：每週哪幾天＋到哪天。資料裡一串只有一筆，讀的時候才展開；只動某一次＝那天跳過、另外拆出一筆一般的行程。
- **今日清單**：一張卡片有標題、細節、重要程度 0–3、排在哪天；今天沒做完的，過了午夜自動順延到今天；每天可以挑一件最重要的事。
  這是簡化版（沒有自訂欄位、步驟、時間窗、估時、封存）。
- **月曆總覽是唯讀的**：它只把行程、清單卡片擺到日期上。要改請到「這一天」。
- **提醒**：SYNOX 還沒有給 pack 用的排程 API，所以這個 pack 不會自己響。加有時間的行程時會附一行
  `/remind_add 13:30 看牙醫 date=2026-11-10`，要提醒就照打。

## 網頁畫面

SYNOX 工具頁按「打開」：**月曆**（整週對齊的格子、可以用開關隱藏某一類）、**這一天**（行程改／標狀態／刪、清單勾選、挑最重要的一件、撞時間）、
**接下來**（30 天、撞時間放最上面）。右上角「＋ 行程」。新增與修改的欄位檢查在伺服器那一側，跟指令是同一份。匯出 `.ics` 是畫面上的下載（先提醒沒有加密）。
還有一個小面板（工具頁內嵌：今天起 7 天＋今天的清單）。

## 別的工具的項目（選用）

月曆可以順便畫別的工具（習慣、旅程、專案…）的日期項目，但 SYNOX 的工具彼此隔離、目前沒有讀別的工具資料的機制，
所以**現在沒有任何來源**，月曆不會出錯、也不會少什麼。之後 SYNOX 若提供這種機制，只要把 `pack.link_sources` 設成一串函式即可（格式見 `engine/links.py`）；
來源壞了、格式不對的列會被丟掉，月曆照畫。**這個工具不含習慣、里程碑、專案**（那些是別的工具的事）。

## 資料與升級

- 資料：`data/calendar.json.enc`（保管箱加密；伺服器版每人一份 `data/users/<id>/calendar.json.enc`），格式 v2（見 `engine/store.py`）。
- **從 0.1.2 升級**：不用做什麼。舊的行程（只有 `day`／`start`／`end`）每次讀的時候先升級（只在記憶體）、下一次寫入才存成新格式；
  **編號不變**，所以舊的 `/cal_rm 3` 照用。沒寫結束時間的舊行程升級後預設一小時。
- `/cal_ics`（Telegram）會在你自己的資料夾（個人版 `data/calendar/files/`、伺服器版 `data/users/<id>/calendar/files/`）暫時寫一個 .ics、
  送出後馬上刪掉，所以 `pack.json` 宣告了 `filesystem:own`。畫面的匯出不經檔案。檔名每次不一樣（`export-<時間>-<亂數>.ics`）。不連網、不開別的程式。
- **0.1.x 的面板為什麼會顯示「讀不到（Failed to fetch）」**：舊面板用 `fetch("/api/packs/calendar/today", {credentials: "same-origin"})`。
  SYNOX 的面板在 `<iframe sandbox="allow-scripts">` 裡跑（沒有 cookie、碰不到 `/api/`），只准用相對網址 `fetch("api/today")`，
  舊寫法被瀏覽器的跨來源規則擋掉，錯誤訊息正是 `Failed to fetch`。0.2.0 改成相對網址。

**個人版與伺服器版**：伺服器版每人一份（用每個人自己的金鑰加密），別人的指令、面板、AI 都看不到；但伺服器的管理者有主金鑰，**解得開每個人的資料**。個人版改成伺服器版時，舊資料不會自己搬（[ADR-0006](../../docs/adr/0006-personal-and-server-mode.md)）。

## 程式結構

`pack.py`（指令、畫面動作、匯出的掛接；`python.package`）→ `bridge/service.py`（指令與畫面共用的核心）、`bridge/text.py`（聊天文字）→
`engine/`（純邏輯：`events`、`weekdays`、`tasks`、`monthview`、`ics`、`links`、`store`；不碰檔案、不連網、不知道 SYNOX）。
