# 🔁 對話接力（claude-relay）

> 🔧 **test（測試中）**，`0.1.0-alpha.1`（尚未實機驗證：只對假的 ClaudeTimerResetter 測過）。
> 🔒 **私人工具**（`"publish": false`）：不進工具庫的 `index.json`、下載連結與公開頁；要用就自己 `python scripts/build.py claude-relay` 打包來裝。

讓「**因為額度（token）停住的 Claude Code 對話**」在你**事先授權**之後，被自動送一句固定的 `continue` 接著做下去。
**只會送 `continue`**：不能送別的字、不能開新對話。這個工具只是一座橋，真正送出去的是你電腦上另外裝好的
**ClaudeTimerResetter**（它的命令列 `python -m claude_timer.cli`，從原始碼跑的那一份；只有 exe 的不能用）。

## 為什麼要有這個

Claude Code 跳出「You've hit your session limit」時會告訴你大概幾點重置。重置的時候你多半不在電腦前面（睡了、出門了），
那個對話就停在那裡等你回來打一句「繼續」。ClaudeTimerResetter 的 resumer 就是為這件事做的：**你判斷好幾點會恢復，時間一到把那個對話接著送出去**
（它的 `docs/resumer.md`）。它刻意不查用量、不做二次確認：你設的時間就是最終決定（它的 `docs/design.md`「為什麼是兩支獨立的工具」）。

這個工具把那件事接到 SYNOX：你可以在手機上用 Telegram 授權、排時間，或讓 SYNOX 的排程到點叫它。

兩條鐵律都照 resetter 的：

- **送出的那一刻，那個對話不能開著。** Claude Code 的一個對話同一時間只能有一個行程持有；還開在 VSCode 裡時接續會秒退、白送。
  resetter 會零成本偵測被佔用。
- **被佔用時只等、不搶。** 關掉別人正開著的對話是破壞性的（沒存的、正在跑的會一起沒掉），所以這個工具**永遠不叫「接管」**：
  用 `at=` 交給 resetter 的排程器時，它到點發現被佔用會每 2 分鐘補試、最多 1 小時；現在就送（沒給 `at`）時被佔用就直接告訴你，不送、不扣次數。

## 應用範例

1. 先找到那個對話：`/relay_sessions`（或 `/relay_sessions cwd=<專案資料夾>`），看它做到哪：`/relay_show <對話> turns=2`。
2. **授權一次**（只有你本人，要手機驗證器）：`/relay_arm <對話> hours=12 uses=3`——接下來 12 小時內、最多 3 次可以被自動接著做。
3. 排時間，兩種選一種：
   - **SYNOX 的排程**：`/schedule_add 06:05 /relay_continue <對話>`。到點由 SYNOX 以「排程」的身分叫它；SYNOX 要開著。
     到點對話若還開著，這一次就不送（沒有補試），隔天同一時間再試（每天的排程）。
   - **resetter 自己的排程器**：`/relay_continue <對話> at=06:05`。把時間交給 resetter 在 Windows 工作排程器註冊一次性的工作，
     SYNOX 關著也會送；到點被佔用會每 2 分鐘補試、最多 1 小時。排的時間一定要在授權期限內——
     但**不保證準時、也不保證在期限內送出**（見「安全模型」：電腦關著錯過的，下次開機才補送）。
4. 搭配 `claude-resetter` 工具：先 `/resetter_usage` 看額度幾點重置，再用上面的方式排在重置之後幾分鐘。
5. 早上看結果：`/relay_jobs`、`/relay_job <編號>`（它最後說了什麼、花多少、改了什麼）。不想再讓它自動做：`/relay_disarm <對話>`。
6. 出事了（一直失敗、花太多、做錯事）：`/relay_freeze`，或請 AI 幫你停（AI 可以凍結，不能解凍）。

## 指令

| 指令 | 做什麼 | 誰能叫 | 要手機驗證器 |
|---|---|---|---|
| `/relay_sessions [cwd=資料夾] [limit=N]` | 列這台電腦上的對話，標出授權過的 | 你、AI | 否 |
| `/relay_show <對話> [turns=N]` | 一個對話做到哪裡 | 你、AI | 否 |
| `/relay_check [<對話>]` | 環境；給了對話就看它現在能不能送、有沒有被開著（不花錢） | 你、AI | 否 |
| `/relay_arm <對話> [hours=12] [uses=3]` | 授權：期限 1–48 小時、次數 1–10；對話要在 resetter 的清單裡，記下它的資料夾 | 只有你 | **要** |
| `/relay_disarm <對話>` 或 `all` | 取消授權（這個工具替那些對話排了、還沒送的工作一起取消） | 只有你 | 否 |
| `/relay_armed` | 授權名單、剩幾次、幾點到期、是否凍結、24 小時內送了幾次、最近 10 筆稽核 | 你、AI | 否 |
| `/relay_continue <對話> [at=時間]` | 對已授權、沒過期、還有次數、沒凍結的對話送 `continue`；`at` 收 `+30`、`06:05`、`2026-11-24 06:05` | 你、**排程** | 否 |
| `/relay_jobs`、`/relay_job <編號>` | 這個工具送出過的工作與結果（只列自己送的） | 你、AI | 否 |
| `/relay_cancel <編號>` | 取消這個工具排的、還沒送的工作 | 只有你 | 否 |
| `/relay_freeze` | 緊急停止：之後所有 continue 一律拒絕，並取消這個工具排的、還沒跑完的工作 | 你、AI | 否 |
| `/relay_thaw` | 解除凍結（連續失敗歸零） | 只有你 | **要** |
| `/relay_setup [home=…] [python=…] [budget=美元]` | ClaudeTimerResetter 的資料夾、要用的 Python、每筆花費上限（預設 2，0.1–20） | 只有你 | **要** |

「只有你」＝你本人在 Telegram／SYNOX 網頁／終端機；AI、排程、手機遠端入口都不行（`pack.json` 的 `callers`，SYNOX 在執行時檢查）。
`continue` 收你本人與排程，**AI 與手機遠端入口不行**。「要手機驗證器」＝SYNOX 的 `stepup`：**沒設定驗證器的人不能用這三個指令**——
這是刻意的：這個工具本來就要求你有驗證器。先在 SYNOX 網頁「安全」設定好，用的時候先 `/unlock <6 位數>`。

## 次數、上限、失敗

- **次數什麼時候扣**：每次叫 resetter 之前先扣一次。只有 resetter **明確證明 claude 沒被叫起來**才退：結束碼 3（被佔用）、
  2（找不到對話）、4（參數不對）。結束碼 1（失敗：claude 可能起來過）、逾時、輸出看不懂**都不退**；
  逾時與看不懂的那一次在稽核標 `unknown:…`，下次 `/relay_jobs`、`/relay_job`、`/relay_continue` 時去 resetter 的工作清單找
  「同一個對話、那段時間建的 continue」補記進來（之後照常追蹤、可以取消、凍結時一起收）。退次數只退回**同一筆授權**
  （中途撤回又重新授權的，不會加到新的那一筆上）。
- **送的同時被凍結或撤回授權**：那一筆在記下來的同一刻再檢查一次，凍結了、授權撤回或過期了就當場叫 resetter 取消、不扣次數，並告訴你。
- 用 `at=` 排好之後你自己取消（`/relay_cancel`）**不退**次數（只會往下，不會變多）。
- **每日上限**：24 小時內最多送出 10 次（所有對話加起來）。被佔用、找不到、參數不對的不算；其他都算。
- **自動凍結**：連續 2 次失敗（叫不動 resetter、resetter 回錯、或之後 resetter 回報那筆工作失敗）就自動凍結，取消還沒跑完的工作，並在回覆裡告訴你。
  工作狀態是在你叫 `continue`、`jobs`、`job` 的時候順便問 resetter 更新的（沒有背景執行緒在看）。有一筆做完（done）就歸零。
- **每筆花費上限**：每次都帶 `--max-budget-usd=<budget>` 給 claude。

## 安全模型（白話、誠實版）

- **送出去的字是寫死的。** 程式裡只有一個常數 `continue`，沒有任何指令有能放自由文字給 resetter 的參數；權限模式也寫死是 `inherit`。
  `inherit` **不等於「一定照原本」**：resetter 從對話紀錄讀你最後一次在 VSCode／終端機互動時的權限模式、模型、effort；
  **讀不到（舊對話、紀錄裡沒有）就退回 `acceptEdits`**（自動同意改檔），原本是 `bypassPermissions` 的**降成 `auto`**。
  relay 從外面看不出它會讀到哪一個，所以 `/relay_arm` 每次都把這件事寫在回覆裡。不會帶「接管」、「分支接續」、「不要求乾淨」、「工具白名單」這些旗標，
  不會叫 resetter 的「釋放佔用」、「開新對話」、「收起改動」。對話 id 只收小寫的完整 UUID，而且放在 `--` 後面；時間只收三種格式。測試鎖住了這些。
- **`continue` 不是無害的。** 它會讓那個對話**帶著它原本的工具權限**接著做它停住前在做的事：改檔、跑指令、推 git，都有可能。
  所以「讓對話可以被續跑」（`arm`）要你本人＋手機驗證器，而且有期限與次數。
- **只收你自己開的對話**：`/relay_arm` 只授權 resetter 清單上來源是 VSCode 或終端機（`entrypoint` 是 `claude-vscode`／`cli`）、
  而且放在專案或分身資料夾（`origin` 是 `project`／`worktree`）的對話；程式用 `claude -p` 開的、暫存或程式自己資料夾裡的、看不出來源的一律拒絕
  （程式開的有自己的主人在管，也沒有「你互動時的權限」可以沿用）。授權前也會跑一次 resetter 的 `check`，送不出去（找不到 claude、
  紀錄或資料夾不見了）就不授權；只是正被開著的照樣授權並提醒你。
- **只授權你信任、而且知道它在做什麼的對話。** 看一下 `/relay_show <對話> turns=2`，確定它停在你願意讓它繼續的地方。
- **不要授權用「略過所有權限（bypass）」跑的對話。** resetter 不會沿用 bypass（會降成 auto，讓分類器擋危險的），但 auto 仍然會放行大部分的動作。
- **背景續跑沒有人能按核准。** 接下來需要你按「同意」的動作會被擋住、停在那裡；用 `/relay_job <編號>` 看它最後說了什麼。
- **用 `at=` 排的工作，SYNOX 管不到執行的那一刻，而且不保證準時、不保證在授權期限內。** 它是 resetter 在 Windows 工作排程器
  註冊的一次性工作，用你平常的帳號環境跑：被佔用時最多補試 1 小時；這個工作設了「錯過就在能跑的時候補跑」（StartWhenAvailable），
  resetter 的 `fire` 也不檢查遲到——**電腦那時是關的，下次開機就會送，可能是授權過期好幾天之後**。
  relay 這邊能做的只有：**每個 `/relay_…` 指令進來時先掃一次**，授權已過期、撤回或換掉、工作卻還沒送的，問過 resetter 之後取消
  （`/relay_disarm` 也會收那個對話還沒送的工作，就算授權已經過期被清掉）。所以電腦關機錯過、而在開機前你沒有打任何 `/relay_…` 指令的話，
  它還是會送。要它一定不跑：在時間到之前 `/relay_cancel`、`/relay_disarm` 或 `/relay_freeze`。
  長期的解法在 resetter 那邊（讓一次性工作帶「最晚到幾點」：`--not-after` 或工作排程器的 `EndBoundary`），這一版沒有改 resetter。
- **重新授權還有效的對話**（`/relay_arm` 同一個對話）＝延長或改次數：算同一筆授權，已經排好的工作照舊；過期之後再授權是新的一筆，
  舊授權排的、還沒送的工作會被掃掉。
- **AI 看得到什麼**：AI 能叫的都是唯讀指令，但只拿得到摘要——`/relay_show` 給 AI 的只有標題、資料夾、時間、輪數（不帶最近幾輪、
  不給最後一句與回覆），`/relay_sessions` 不給「你最後說的話」，`/relay_job` 不給它最後說的原文、改動摘要壓成一行。
  對話內容只有你本人打指令才看得到。`/relay_show` 也只看 resetter 一般清單列得到的對話（暫存、程式開的不給看）。
- 稽核（`/relay_armed` 最下面）記：時間、動作、來源（你本人／排程／AI／系統）、對話 id 前 8 碼、結果；只留最近 200 筆；**不記驗證碼、不記對話內容**。

## 這一版沒有做什麼（以及為什麼）

| 沒做的 | 為什麼 |
|---|---|
| 送任意文字（`resume` 帶你自己寫的話） | 任意文字就是 prompt injection 的入口：只要有一條路能把別人的字送進一個有工具權限的對話，就等於把那些權限交出去。需要資料夾白名單、風險分級、兩組驗證、預設凍結，才值得開（設計草案在 `docs/adr/0010-claude-relay-continue-only.md`） |
| 開新對話（`new`） | 同上，而且新對話沒有「原本的權限」可以沿用 |
| 自動辨認「被額度停住的對話」 | resetter 還沒有這個偵測；而且要先想清楚：誰可以選、會不會被利用（例如讓別的對話假裝停住） |
| 搶佔（接管、釋放佔用） | 會關掉你正在用的 Claude Code，沒存的東西會沒掉 |
| 現在送、被佔用時自動補試 | resetter 只在 `--at` 的工作補試；現在送被佔用時，這個工具直接告訴你，不留一筆沒人管的等待中工作 |

## 設定

1. 在 Windows 上 clone ClaudeTimerResetter、跑一次它的 `scripts\setup.bat`（建好 `.venv`）。
2. 在 SYNOX 設定好手機驗證器，`/unlock <6 位數>`。
3. `/relay_setup home=<ClaudeTimerResetter 的資料夾>`（要別的 Python 再加 `python=…`；`budget=1.5` 改每筆花費上限）。
4. `/relay_check` 確認叫得動。

## 資料存哪

全部在 SYNOX 的保管箱（`pack.store.of(user)`，密文）：設定、授權名單（對話 id、資料夾、分支、期限、剩幾次）、凍結旗標、
24 小時內送出的時間、這個工具送出的工作編號與狀態、稽核。每次叫 resetter 的輸出暫存在 `pack.path_of(user, "calls", …)`，讀完就刪。
對話本身、resetter 的工作清單與 log 都在 resetter 自己的資料夾，這個工具不讀不改。

## 能力宣告

`capabilities: ["filesystem:own", "subprocess"]`：叫完 resetter 就刪掉自己資料夾裡的輸出暫存檔（`filesystem:own`）；只經 SYNOX 的 JobRunner（`app.jobs`）開 `python -m claude_timer.cli …`（argv 陣列、不經 shell、有逾時、
子程序環境拿掉像密鑰的變數）。不連網、不動態執行；只給擁有者（`access: owner`）。
