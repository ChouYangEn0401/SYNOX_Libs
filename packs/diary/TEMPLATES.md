# 題組：內建的有哪些，怎麼自己寫一個

「題組」就是**今天要回答哪些問題**。程式裡沒有寫死任何一題——每個題組都是一個 JSON（內建的在 `content/templates/`），
可以改、可以刪、可以自己做一個。這份是原專案 `docs/templates.md` 的 SYNOX 版。

## 內建題組一覽（41 個）

原本的每日日記內建 **21 個**（原本的說明寫「20 個」，少算了 `jot`），2026-11 又新設計了 20 個。
新的裡面 8 個預設就出現；另外 12 個內建、但預設不出現（題組檔寫 `"default_hidden": true`）：`/diary_setup` 列得出來，
`/diary_tpl_restore <id>` 拿出來。不喜歡的可以刪（`/diary_tpl_rm`），刪掉之後不會自己跑回來；想拿回內建的：`/diary_tpl_restore <id>`。

> 內建這些題組都是往同一個方向問的：看清楚今天發生了什麼、對自己誠實、找出下一步。

### 簡單記一下

| 題組 | 約幾分鐘 | 什麼時候用 | 預設 |
|---|---|---|---|
| **隨手記 · 一則一則** `jot` | 2 | 不想選題目，想到什麼就一則一則記下來的時候（Telegram 上的 /diary 就是存在這一組）。 | 原本就有 |
| **三行日記** `three-lines` | 1 | 只有一分鐘：一件事、一個感覺、一件謝謝。最不容易斷掉的那一種。 | 原本就有 |
| **感恩清單** `gratitude` | 3 | 想把注意力放回好的事情上：三件小事，加上一個人。 | 原本就有 |
| **晚間回顧（三分鐘）** `evening-review` | 3 | 每天睡前；不談信仰也能用。 | 新 |
兩個核心的長版練習：

- **高峰與低谷** `peaks-valleys`：今天最開心和最難受的各一件事，各問到底。高處問「這裡面有多少不是我自己掙來的」
  「如果三個月後我因此驕傲，會從哪裡開始」；低處問「哪些是我能決定的、哪些不是」「信靠神在這件事上具體要做什麼」。
  最後一段把高的和低的放在一起看，因為它們常常在講同一句話。
- **反思膠囊** `capsule`：一件事想到底——發生什麼、我的感受、學到什麼、**哪一段經文用得上**、**哪個有智慧的人說過的話用得上**、
  我現在怎麼看它。經文那兩題是綠色 `#1f7a4d`，人的智慧那兩題是藍綠 `#2f7d86`，輸出時看得出來哪句話從哪裡來。
  一天做一塊就夠（空白的段落輸出時不會出現）。

哀歌 `lament` 刻意留了位置給說不出口的話：「就算什麼都還沒改變，我仍然相信的是」那一題有一個選項是「我不確定，但我還在這裡」。
決策紀錄 `decision-log` 有一段是「事後回來寫」，當天空著沒關係：重點是把「決定好不好」和「結果好不好」分開。

## 一個題組長什麼樣

最短的一個，完整可用：

```json
{
  "id": "my-three",
  "name": "我的每日三問",
  "description": "睡前三分鐘。",
  "group": "簡單記一下",
  "order": 50,
  "sections": [
    {
      "id": "night", "title": "睡前", "color": "#2456b8", "icon": "☾",
      "fields": [
        { "id": "best", "label": "今天最好的一刻", "kind": "short_text" },
        { "id": "learn", "label": "學到什麼", "kind": "text" },
        { "id": "mood", "label": "今天整體", "kind": "scale",
          "options": [ { "id": "good", "label": "好" }, { "id": "ok", "label": "普通" }, { "id": "bad", "label": "不好" } ] }
      ]
    }
  ]
}
```

存進來：`/diary_tpl_save {…整個 JSON…}`（AI 幫你做也是走這個）。一個欄位最多 2000 字：比較大的題組，
放進「匯出全部」格式的 JSON（`{"format": "synox.diary.export", "version": 1, "templates": [ {…} ]}`），
存成你資料夾的 `import.json`，再 `/diary_import`。**沒寫的鍵就用預設值**，所以檔案可以很短。

## 題目的七種型態

| `kind` | 原本編輯器長什麼樣 | 存起來的樣子 |
|---|---|---|
| `text` | 大輸入框，可以換色 | HTML 字串（只收 `<b> <i> <u> <s> <br> <span style="color">`） |
| `list` | 可增可減的編號行 | 字串陣列 |
| `short_text` | 一行 | 字串 |
| `choice` | 一排藥丸，點一下選起來 | 選中的 `option.id` |
| `multi_choice` | 同上，可複選 | `option.id` 陣列 |
| `scale` | 同上，有順序（滿意→缺乏；1–5 分也用它） | 選中的 `option.id` |
| `fill` | 句子裡的 `{}` 變成行內填空 | 字串陣列，一格一個 |

`choice`／`multi_choice`／`scale` 需要 `options`；`fill` 需要 `pattern`（例：`"我想成為一個 {} 的人，因為 {} 。"`）。
輸出時填進去的字會變粗、上色，沒填的地方印成 `＿＿＿＿`。

## 每個鍵是什麼意思

### 題組

| 鍵 | 預設 | 說明 |
|---|---|---|
| `id` | — | 英數字、`-`、`_`。 |
| `name` | — | 顯示的名字。 |
| `description` | `""` | 名字底下那一行小字。 |
| `group` | `""` | 分類標題（與神同行、心情與難處、成為什麼樣的人、工作與創業、簡單記一下）；留白的歸到「其他」。 |
| `order` | `1000` | 排序，小的在前面；同數字照 id 排。 |
| `when` | `""` | **什麼情況用它**，一句話。挑題組時人看，AI 也看。 |
| `minutes` | `0` | 認真寫一次大概幾分鐘。 |
| `moods`、`tags` | `[]` | 適合的心情、短標籤（挑題組的規則會看）。 |
| `structure` | 照段落數 | `one-part`／`three-part`／`n-part`。不寫就照 `sections` 的數量算。 |
| `reflection` | `none` | 一道階梯：`none` 只記錄、`reflection` 有反思（不談信仰）、`devotional` 在神面前反思／有經文、`prayer` 再加禱告／代禱／哀歌。 |
| `flow` | `[]` | 走過哪些步驟、照什麼順序：`checkin`、`events`、`feelings`、`worries`、`work`、`decision`、`identity`、`review`、`scripture`、`reflection`、`confession`、`gratitude`、`prayer`、`trust`、`people`、`quote`、`plan`。不在字彙表裡的值＝題組不合。 |
| `default_theme` | `letterpress` | 紙張顏色：`letterpress`／`notebook`／`linen`／`dawn`／`midnight`。 |
| `default_layout` | `letter` | 輸出版型：`letter`／`ledger`／`manuscript`／`postcard`。 |
| `closing_label`、`closing_hint`、`closing_placeholder` | `給主的話`… | 最後那個自由書寫欄叫什麼（不談信仰的題組改成「寫給自己的話」「補充」…，輸出跟著改）。 |
| `default_hidden` | `false` | SYNOX 版多的：內建、但新使用者預設不出現（`/diary_tpl_restore` 拿出來）。 |
| `sections` | `[]` | 段落。 |

### 段落與題目

| 鍵 | 預設 | 說明 |
|---|---|---|
| 段落 `id`、`title` | — | 同一個題組裡 id 不能重複。 |
| 段落 `color` | `#2f3437` | 這一段的主色：色條、標題、預設墨水色都跟著它。 |
| 段落 `icon` | `null` | 標題前的小圖示，一到兩個字元。 |
| 題目 `id` | — | **改了 id 等於換一題**，舊答案會變成「這個題組沒有的內容」（不會被刪，換回去就看得到）。 |
| 題目 `label`、`kind`、`options`、`pattern` | | 見上面。 |
| `placeholder`、`min_rows` | | 原本編輯器用的提示字、`list` 一開始給幾行。 |
| `color` | `null` | 這一題答案的預設墨水色，不寫就跟著段落。 |
| `hint` | `null` | 只在原本的編輯器裡看得到的小提醒，不會印到輸出上。 |
| `ai_hint` | `null` | **給替你填的 AI 看的**：這一題要從日記裡抓什麼、什麼情況留空。輸出看不到。 |

## 寫題目的幾個心得

- **能用勾的就不要用寫的。** 最常見的失敗不是寫得不好，是那天沒有寫。
- **一題只問一件事。** 「今天過得怎樣、有什麼想法？」沒人答得出來。
- **把「事實」和「我的解讀」分開問。** 這是 `hard-day` 的整個重點。
- **留一個誠實的選項。** 「怕做錯」「其實不想做」「在裝有把握」——沒人願意打字寫出來，但願意勾。
- **問完感覺，要給一個出口。** 每個處理情緒的題組最後都有「今天還做得到的一件小事」。
- **空著也要能看。** 空白的題目輸出時自動略過，題目可以多給一點。
- **用顏色分開不同來源。** `capsule` 經文綠色、人的智慧藍綠色。
- **問完之後要有一個往外的題目、加一題會讓人停一下的。** 趕的時候最容易略過的，通常就是最該問的那一題。

## 分享出去

一個題組就是一個 JSON：傳給別人，對方 `/diary_tpl_save` 就能用。整本搬家用 `/diary_export_all`（日記＋題組＋版型＋設定）；
匯入預設是**合併**，只會增加，不會蓋掉原本的東西。
