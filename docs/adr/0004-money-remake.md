# ADR-0004：記帳 0.4.0——從一套本機記帳程式通用化成多檔工具

- 狀態：**已實作**（記帳 0.4.0，alpha）。
- 範圍：`packs/money`（0.3.1 → 0.4.0）；取代 [ADR-0002](0002-money-general-version.md) 的資料與指令部分、
  延伸 [ADR-0003](0003-tool-apps-and-money-app.md) 的記帳 app。
- 細節（名字、欄位、值怎麼寫、檔案歸屬）在 `packs/money/CONTRACT.md`；這份只寫決定與理由。

## 背景

0.3.x 的記帳是單檔工具：一份 JSON 存在 SYNOX 保管箱，功能只有記帳、類別、每月預算與單類上限。

維護者另外有一套自己在本機用了一段時間的記帳程式（一個人用、不公開）：有預算的每一格、滾存、信用卡帳單對帳、分期、
週月檢討、投資與資金操盤，以及一個六個分頁的網頁畫面。邏輯成熟、有大量測試，但它是給一個人、一台電腦寫的：
資料夾位置靠環境變數、時區與平日寫死、用途代號與類別名帶個人用語、起始類別與關鍵字有品牌名、還接著幾個外部工具。

這一版把它的**邏輯層原樣搬進工具庫**，換掉所有個人化與「只有一個人」的假設，接上 SYNOX 的指令、畫面與隔離。

## 決定

### 1. 多檔 python 工具

- `pack.json` 寫 `"python": {"module": "pack", "package": true}`：`pack.py` 以套件身分載入，`bridge/`、`engine/` 用相對 import。
  這是 SYNOX 本體新加的能力（多檔工具：子模組一律從原始碼編譯、有鎖時每個檔對雜湊、不加 `sys.path`、不同工具的同名模組互相看不到）。
- 為什麼不維持單檔：引擎約 60 個模組、上萬行，塞進一個檔就等於放棄原本的測試與結構。
- 代價：舊的 SYNOX 載不起來（`requires.synox` 要等 SYNOX 發佈含多檔支援的版本再收緊）；安裝檔變大（仍在 5 MB／300 檔的上限內）。

### 2. 兩層：engine 與 bridge

```
pack.py   install()：把 bridge 的指令表掛到 SYNOX（指令、畫面的讀／動作／匯出、小面板）
bridge/   SYNOX ↔ engine：一個領域一個檔（ledger、home、plan、setup、flow、review、piggy、compat）
          每個 run 只做「字串欄位 → 引擎參數 → 呼叫 services → 組回覆」；同一個 run 給指令（回文字）也給畫面（回資料）
engine/   邏輯層：原樣搬，只做機械改動（資料夾位置、合併 schema、拿掉第三方驗證套件、中性的用途代號、
          類別用系統代號找、時區與幣別改成帳本設定、乾淨的起始檔）
app/      完整畫面：原本的六個分頁原樣搬；只重寫入口頁與轉接器（呼叫改成 SynoxApp.read／act／download）
```

- 為什麼分層：引擎可以完全不靠 SYNOX 單獨測（`tests/money/engine/`），SYNOX 的規矩（欄位都是字串、每個動作是同名指令、
  危險程度、誰可以叫）只在 bridge 處理一次。
- 金額與日期的解讀全工具只有一套（`bridge/table.py`）：帳本裡一律存最小單位的整數，小數位數是帳本設定；
  人打的字照小數位數換算，畫面送來的已經是最小單位——分辨靠「從哪一層進來」（`book.screen`），不靠呼叫者的種類。

### 3. 帳本：自己資料夾裡的 SQLite，沒有加密

- 每個人一本帳，放在 `pack.path_of(<這個人>, "book")`：帳本檔、每日備份（留 14 天）、封存、收據都在裡面。
- **沒有加密**。畫面、說明、匯出前的提醒都照實寫。0.3.x 的保管箱只用來讀舊資料。
- 為什麼這次不加密：引擎靠 SQLite 的查詢與交易；放進保管箱等於每次用都要整本解開、寫回，第一版先求邏輯正確。
- **日後要加密只動 `bridge/session.py` 的 `_connect`／`_close`**：其他檔都只拿 `book.conn`，不知道檔案在哪、有沒有加密。
- 整本匯出只能是 CSV（SYNOX 的匯出規定）：每一列是「表名＋那一列的內容」。

### 4. 隔離規則（硬規則，有閘門測試）

1. 帳本位置只從 `pack.path_of` 來；引擎的「資料夾在哪」每次呼叫用 `contextvars` 明確設定，沒設定就丟錯——不讀環境變數、
   不退回任何共用位置（原本靠環境變數，同一個程序多條執行緒會互相蓋掉）。
2. 只有 `session.open_book(pack, user)` 能開資料庫；每次呼叫開、用完關；連線不放在模組或 pack 上。
3. engine 與 bridge 沒有模組層級的可變狀態、不寫環境變數。
4. 畫面與指令的參數裡沒有「使用者」「路徑」欄位；使用者只從 SYNOX 的登入身分來。猜別人的編號只會在自己的帳本裡找不到。
5. 匯入、附檔、備份、封存都在這個人的資料夾裡，檔名擋 `..` 與絕對路徑；錯誤訊息不帶路徑。
6. 每個人一把寫入鎖；改動紀錄的「誰」寫 `synox:<來源>`，不寫名字。
7. SYNOX 的保管箱（`pack.store`）只有轉舊資料的那個檔能用，而且一定是 `.of(user)`。

閘門：`tests/money/test_isolation.py`（兩個人交錯跑每個讀、動作、指令；一個人做完所有動作另一個人的檔一個位元都不變；
兩條執行緒各記 200 筆）、`tests/test_gates.py`（記帳只准用列出的標準庫；碰檔案、開資料庫、開鎖只准在列出的幾個檔；上面的靜態規則）。

### 5. 通用化

- 用途代號改成中性的（`giving`、`fixed`、`saving`、`living`、`invest`、`debt`）；畫面上的名字是資料、可以改。
- 程式不靠類別名字找類別：每個類別多一欄系統代號（例 `card_payment`、`meal.lunch`），有代號的類別可以改名、不能停用或換種類。
- 幣別（代號、符號、小數位數）、每期起算日、時差、午餐提醒的星期幾、週報的星期幾都是帳本設定。
- 起始類別只放通用詞；關鍵字與比對規則不放任何品牌、店名、平台名（`tests/money/test_deid.py` 把這條變成測試）。
- 給 AI 的手冊重寫成總表＋主題檔；AI 檢討改由 SYNOX 自己的 AI 讀「報表數字」、寫完用「存檢討」存回，不再叫外部工具。
- 撲滿（投資）沒有證券帳戶、也沒開選配時不出現；不含任何券商的對帳單匯入；基準不預設代號。
  引擎的價金與損益還只會算整數元，所以小數位數不是 0 的帳本先不開放撲滿。

### 6. 取代 ADR-0002 的哪幾條

- 資料：不再是保管箱裡一份 JSON（schema 2），改成每人一本 SQLite（第 3 節）。0.3.x 的資料第一次開新版時自動轉入（一批寫入、可撤銷），
  舊資料另存一份不刪。
- 類別：從「自己打字就有」的平面清單，改成「用途 → 大類 → 細項」三層，加系統代號；舊的範本名（基本、帳單、存錢與投資、捐贈、收入）還收。
- 預算：每月總預算＝生活費那一格；單類上限＝細項的預設預算。
- 指令：舊指令名全部保留（第 0.3.x 版能打的這一版都能打）；新功能用新指令名。
- ADR-0002「程式不靠類別名字」那一條這一版做到了（系統代號）。

## 已知代價

- 帳本沒有加密（第 3 節）。
- 需要支援多檔工具的 SYNOX。
- 不能自動退回 0.3.x：新記的帳在 SQLite 裡，0.3.x 讀不到；退回後看到的是升級前那一份舊資料。
- 畫面的檔是原樣搬來的大檔（總覽、撲滿各數十 KB），這次不拆（1:1 優先）。
- 帳本從檔案匯入沒有畫面（SYNOX 畫面還沒有上傳），用指令讀自己資料夾裡的檔。
