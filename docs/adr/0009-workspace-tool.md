# ADR-0009：工作區工具（workspace）——一份固定菜單，讓 SYNOX 看資料夾、建專案，繞不出菜單

- 狀態：**提案**（2026-11-18；還沒有程式）。第一版只做 v0（下面第 5 節）。
- 範圍：新工具 `packs/workspace`。不改 SYNOX 核心。
- 讀者：之後接手開發的人與 Claude。名詞白話解釋放在第 1 節。

## 1. 一句話與白話名詞

**一句話**：給 SYNOX 一個「電腦環境操作」的工具，但它只會做一張**寫死的菜單**上的幾件事，
而且只碰一個指定的「工作區」資料夾；沒有任何一條路可以叫它執行菜單以外的事。

| 名詞 | 意思 |
|---|---|
| 菜單（action catalog） | 工具能做的事的完整清單。每一項是一段固定的程式，不是「執行一句話」。新增能力＝新增一項、審過、加測試 |
| 格子（slot） | 一項動作需要使用者填的資料，例如資料夾名字。每個格子有型別與嚴格檢查，沒有「任意字串」這種型別 |
| 工作區（workspace root） | 工具唯一可以碰的資料夾。由使用者在設定裡指定；範圍之外的路徑一律拒絕 |
| 禁區（deny list） | 就算在工作區裡也不准碰的東西：金鑰、密碼、瀏覽器資料、`.env`、`.git/hooks`、`.ssh` 等 |
| 注入（injection） | 有人把惡意的字塞進 AI 會讀到的地方（網頁、檔案、訊息），讓 AI 或工具把它當指令做 |
| shell | 把一整串文字當成指令解讀的程式（PowerShell、cmd）。`;`、`&&`、`\|`、`` ` `` 這些符號在 shell 裡能接上別的指令，是注入的主要入口 |

## 2. 背景：為什麼不做「讓 AI 執行指令」

想要的功能：透過 SYNOX 讀電腦的資料夾、建專案、之後也許跑指令。難處：

1. **黑名單擋不住**。擋 `rm -rf` 沒用：`python -c`、`powershell -enc`、`find -exec`、`git -c core.fsmonitor=…`、`xargs` 都能做同樣的事。
2. **組合攻擊**。幾步各自無害，合起來有害：
   寫一個 `.bat` 再執行它；寫 `.git/hooks/pre-commit` 再 `git commit`；`git config core.fsmonitor …` 再 `git status`；
   改 `package.json` 的 scripts 再 `npm test`；建一個 junction（資料夾捷徑）連到工作區外再「寫進工作區」；讀了金鑰檔再用網路送出去。
   逐條檢查指令抓不到這些。
3. **「有限指令加自由參數」也不安全**：參數可以夾帶旗標（`--upload-pack=…`、`-c …`）、`..`、以 `-` 開頭的檔名。
4. **最大的威脅是注入**，不是使用者本人：AI 讀到惡意內容，照著做。
5. **SYNOX 在 Windows 現在沒有沙盒**（預設 `none`，SYNOX ADR 0022 §6）。程式跑起來就是這個使用者帳號的全部權限。
   所以「執行指令」這一層目前沒有最後防線，不能開。

結論：**不要做「過濾指令的守門員」，做「根本沒有危險功能可叫的菜單」。**
類比：自動販賣機沒有「給我現金」的按鈕，不是因為它檢查你有沒有惡意。

## 3. 決定

| # | 題目 | 決定 |
|---|---|---|
| 1 | 形狀 | 工具只暴露一份菜單；每一項是寫死的 Python 函式。**程式裡不存在「執行任意字串」、「執行任意程式」的路**（不 import `subprocess`、不用 `os.system`、不用 `eval`／`exec`；測試用靜態檢查守住這點） |
| 2 | 輸入 | 每個格子有型別：`name`（`[a-z0-9][a-z0-9-]{0,39}`，不以 `-` 開頭）、`int`（範圍）、`choice`（固定清單）、`rel_path`（相對工作區的路徑，見 #4）。**沒有任意字串型別**。檔案內容只在「寫入」類動作裡出現，且只寫成資料，不執行 |
| 3 | 誰能用 | `access: owner`。每個會改東西的指令 `callers: ["human"]`（AI、排程、遠端不能叫）；建專案這類 `effect=DANGER`（先送確認卡，內容是這次要建的完整檔案清單）。用 SYNOX 現成的門禁核心（SYNOX ADR 0025），不自己寫 |
| 4 | 路徑 | 一個函式 `resolve(rel_path)` 是**唯一**把使用者輸入變成真實路徑的地方：拒絕絕對路徑、磁碟機代號、`..`、`:`（NTFS 資料流）、保留名（`CON`、`NUL`…）、結尾空白或點；**解開 symlink 與 junction 後**，確認結果仍在工作區之內；再比對禁區。所有動作都只呼叫它 |
| 5 | 工作區 | 由設定指定的**一個**資料夾；沒設定＝工具什麼都不做並說明怎麼設。預設建議 `Documents\SYNOX_Workspace`（新建的空資料夾）。工作區本身不可以是磁碟根目錄、使用者家目錄、或包含禁區的資料夾（設定時檢查） |
| 6 | 工具寫出的東西不執行 | 這個工具寫出的檔（含範本複製出來的）**永遠不由這個工具執行**；範本裡不可含可執行副檔名（`.bat`、`.cmd`、`.ps1`、`.exe`、`.vbs`、`.js` 等），也不可寫 `.git/hooks`。這一條擋掉組合攻擊的主要形式 |
| 7 | 能力宣告 | `capabilities: ["filesystem:any"]`（要讀工作區，不是工具自己的資料夾）。**不宣告** `subprocess`、`exec`、`network`。這會讓安裝報告標紅，這是對的：使用者要看到並同意 |
| 8 | 輸出 | 一律截長度（單次回覆與單檔讀取有上限）；二進位檔不回內容，只回大小與類型；不回環境變數；錯誤訊息用固定句子，不把輸入原樣吐回去 |
| 9 | 稽核 | 每個改東西的動作寫一行紀錄（動作名、目標相對路徑、成功與否），**不含檔案內容** |

## 4. 路徑檢查要擋的清單（測試必須逐項涵蓋）

`..\x`、`a/../../x`、`C:\Windows`、`\\server\share`、`\\?\C:\…`、`x:stream`、`CON`、`nul.txt`、`name.`、`name `、
URL 編碼的斜線與 `..`、雙重編碼、Unicode 全形的斜線與點、空位元組、超長路徑、
工作區內的 junction／symlink 指向外面、**先建 junction 再用它寫入**（兩步組合）、
`.git/hooks/*`、`.env`、`.ssh`、`_keys`、瀏覽器資料夾（Chrome、Edge、Firefox 的使用者資料）、
以 `-` 開頭的名字、大小寫變化（Windows 不分大小寫）、8.3 短檔名（`PROGRA~1`）。

## 5. 分階段

| 階段 | 內容 | 狀態 |
|---|---|---|
| **v0** | 第 0 層**瀏覽**（`ls` 列資料夾、`read` 讀文字檔、`tree`、`find` 依名字找）＋第 1 層**建專案**（`new <範本> <名字>`、`mkdir`；範本是工具內建的固定檔案組，例如 python-cli、空專案）。不執行任何程式 | **要做** |
| v1 | 白名單指令：`git status`／`log`／`diff`（唯讀）、`pytest`。每一項是寫死的模板，旗標常數、格子有型別、**不經 shell**、不帶環境變數（清掉 `GIT_*`）、逾時、輸出上限；要手機驗證器解鎖（`stepup`）加確認卡 | **不做**，等 v0 用過；仍受 #6 限制 |
| v2 | 較自由的指令執行 | **不做**，等 SYNOX 沙盒（ADR 0022 §6）或容器隔離完成。沒有隔離就不開 |

## 6. 為什麼不先做沙盒或 Docker

菜單與隔離是不同的兩層：菜單讓壞事**不會發生**，隔離讓壞事**萬一發生也不擴散**。最終兩層都要。
v0 的動作本身不危險，所以不必等隔離。隔離屬於 SYNOX 核心（ADR 0022），不在這個工具庫做。
Docker 對 Windows Home 要靠 WSL2、常駐吃記憶體，對一般使用者太重；比較適合在雲端或另一台電腦用。

## 7. 驗收

- `pytest -q tests/test_workspace.py` 全過，且**攻擊測試**涵蓋第 4 節每一項（各至少一個案例，斷言「被拒、且工作區外沒有任何檔案被建立或改動」）。
- 靜態測試：`packs/workspace/` 底下沒有 `subprocess`、`os.system`、`os.popen`、`eval`、`exec`、`__import__`、`ctypes`、`socket`、`urllib`、`requests`（測試掃原始碼）。
- 組合測試：建專案後，確認產生的檔案沒有可執行副檔名、沒有 `.git/hooks`；建 junction 再寫入的情境被擋。
- `python -m synox.sdk check packs/workspace` 結束碼 0。
- 照 [CONTRIBUTING-TOOLS.md](../CONTRIBUTING-TOOLS.md) 第 4 節補齊 `test_gates.py`（`ALLOWED_CAPS`）、`test_build.py`（`SMOKE`）、`test_access.py`。
- 版本 `0.1.0-alpha.1`、`stage: alpha`（沒在真的 SYNOX 實機試過）。

## 8. 不做的事

- 不做「執行這句話」、不做 shell、不做「讓 AI 選指令」。
- 不用黑名單當主要防線。
- 不讀禁區、不碰工作區以外。
- 不從工具裡安裝套件、不連網。
- 不在這個工具裡自己做沙盒或加密。

## 9. 還沒決定

| 題目 | 建議 |
|---|---|
| 工作區資料夾預設位置 | `Documents\SYNOX_Workspace`，由使用者在設定中確認 |
| 要不要讓它讀既有專案 | 預設不讀；使用者可以另外加入「唯讀根目錄」，加入時要手機驗證器解鎖 |
| 內建範本有哪些 | v0 只放 `empty` 與 `python-cli`；其他之後逐個審過再加 |
| 伺服器版（多人）要不要開 | 不開。單人版專用（`access: owner`） |
