# 待做：🔐 加密工具（encrypter）

狀態：**待做**（構想與已定的細節先記在這裡；還沒有程式）。開工前先跟維護者確認下面「下次開發時決定」那幾項。

## 想做成什麼

一個方便好用的 SYNOX 工具：用公開標準 **OpenPGP** 加密、解密**訊息**與**檔案**，讓私密的東西可以安全地傳、安全地放。

- **不自己寫加密演算法**：工具只是一層接口，實際加解密交給一個已經存在、可信任的 OpenPGP 實作
  （參考：`<下次開發時決定：要接哪一個加密程式或函式庫>`）。沒有那個程式的人，用一般的 `gpg` 也要解得開（同一個標準）。
- 跟 SYNOX 的「工具簽章」（`pack.sig.json`，證明誰做的、沒被改）是兩回事：這裡是「別人看不到內容」。兩組鑰匙不混用。

## 要有的功能

| 功能 | 說明 | AI 可以叫嗎 |
|---|---|---|
| 加密一段訊息 | 選收件人的公鑰 → 得到一段可以貼出去的密文 | 可以 |
| 加密檔案 | 只能加密使用者允許的資料夾裡的檔；原檔保留、不覆蓋已存在的檔 | 可以 |
| 看密文是誰加密的 | 貼一段密文或給一個檔 → 告訴你是用哪把公鑰（指紋）加密的、要哪把私鑰才解得開；**不解密** | 可以 |
| 列出公鑰 | 名字、指紋、建立日期 | 可以 |
| 匯入公鑰 | 從檔案或貼上；顯示指紋讓使用者確認 | 只能使用者本人 |
| 解密 | 需要私鑰與密語 | **只能使用者本人** |
| 產生一組金鑰 | 需要設密語 | **只能使用者本人** |

### 加密紀錄
- 做過的加密訊息存成紀錄：給誰（公鑰名稱與指紋）、哪天、密文本身。密文本來就是加密的，存起來也安全；
  紀錄存在工具自己的加密儲存（vault）裡。
- 列表看得到「這段是用哪把鑰匙加密的」，之後要解、要轉寄都找得到。

### 解密時怎麼拿密語
- 使用者貼一段密文進來 → 工具先看出它是用哪把鑰匙加密的 → **SYNOX 跳出「加密入口」請使用者在那裡輸入密語**。
- 密語、私鑰、解密後的內容**都不經過 AI**：不進聊天紀錄、不寫日誌、不放進 AI 看得到的回覆；解出來的內容只顯示在工具畫面上，
  有「清掉」按鈕。聊天裡打解密指令只回「請到工具畫面解」。
- 依賴 SYNOX 核心的「加密入口」（`/secret-msg`；設計中，防護等級已定：瀏覽器內加密＋加密程式被改過會出現警告）。
  在那之前：解密、產生金鑰只在工具畫面上做，密碼欄位不顯示明碼（需要 SDK 的密碼欄位）。

## 安全規則（照 SYNOX_Libs 的閘門）
- 只有擁有者能用（`access: owner`）；危險動作（產生金鑰、刪公鑰、解密）`ai=False`，必要時要手機驗證（step-up）。
- 私鑰：工具**只記路徑或交給加密程式自己的金鑰環**，不複製私鑰內容、不放進工具資料夾、不經過網路。
- 檔案只能在使用者加進來的資料夾裡（解析真實路徑後檢查，擋 `..` 與捷徑跳出）；不能加整顆磁碟根目錄。
- 權限照實宣告（會執行外部程式就宣告 `subprocess`；會讀寫使用者選的檔就宣告 filesystem）。
- 測試只用測試用的拋棄式金鑰與暫存資料夾。
